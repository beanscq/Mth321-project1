## 模型（权威，请勿改动）

```
y1' = -0.04*y1 + 1e4*y2*y3
y2' =  0.04*y1 - 1e4*y2*y3 - 3e7*y2^2
y3' =  3e7*y2^2
y(0) = [1, 0, 0],   t in [0, 40]
```

反应名称只是助记：`r1 = k1*y1`（A→B）、`r2 = k2*y2^2`（2B→B+C，**净** −1 B / +1 C）、
`r3 = k3*y2*y3`（B+C→A+C）。按题目要求，显示的 `3e7*y2^2` 项**不再乘 2**。
不变量 `(1,1,1)·f ≡ 0` 在测试里有断言。

## 不可破坏的约定

**1. 只有一个比较网格。** `[1e-8, 40]` 上包含 `t = 0` 在内、不少于 200 个对数间隔的输出时刻
（总共 201 点）。各求解器自行选择内部步长；**每个方法以及参考解**在比较之前都要插值到这个网格上。

**2. 插值阶必须不低于方法阶。** 密化输出用**三次 Hermite**（`config: interpolation.scheme`）。
线性插值的误差是 `O(h^2)`，会把 RK4 的观测收敛阶压到 2，从而悄悄毁掉整个收敛性研究。
这是硬性要求，不是风格选择。

**3. 约化 Jacobian 是投影，不是子矩阵。** 消去 `y3 = 1 - y1 - y2` 得到 `B_red = S·J·T`，即

```
B_red = [[ -k1 - k3*y2 ,    k3*y3 - k3*y2          ],
         [  k1 + k3*y2 , -k3*y3 + k3*y2 - 2*k2*y2  ]]

tr(B_red)  = -k1 - k3*y3 - 2*k2*y2                  (= tr J)
det(B_red) = 2*k2*y2*(k1 + k3*y2) = 2.4e6*y2 + 6e11*y2^2
```

若改成取 `J` 的左上 2×2 块，就会丢掉 `6e11*y2^2` 这一项：在 `t = 40` 处那会让行列式差 3.3 倍，
并把 `S(40) = 1.58e5` 变成 `5.2e5`。证书 `m2(J) == det(B_red)`（主 2×2 余子式之和）在
`tests/test_model.py` 里被断言，并由 `eigen.consistency_check` 在全时程上复核。

**4. 结构零特征值。** `(1,1,1)^T f ≡ 0` ⇒ `(1,1,1)^T J ≡ 0`。刚性比**只用两个非零特征值**，
判别用两条互相独立的途径：量级阈值（`|Re λ| ≤ 1e-8 · max|Re λ|`），以及与精确左零向量
`(1,1,1)/√3` 的对齐程度。

**5. `t = 0` 是退化点。** 那里 `y2 = y3 = 0`、`B_red = [[-0.04, 0], [0.04, 0]]`，所以那两个
「非零」特征值里有一个恰好为零；完整 Jacobian 有一个*二重*零特征值。`t = 0` 处不报刚性比；
所有图都从第一个正的输出时刻开始。

**6. 密化输出是免费的，而且不允许它成为瓶颈。** `f` 在每个步节点都存下来，且每个方法都是用
它**本来就要做**的一次求值得到的（显式 Euler 与 RK4：新节点处的值就是下一步的第一次求值；
隐式 Euler：Newton 最后一次残差求值）。因此 Hermite 插值额外增加**零**次右端函数求值，
F8 也就不需要「阶数被实现细节卡住」这类免责声明。这一点是被检验过的：RK4 在**完整**网格上的
拟合阶（4.23）与在 `t ≥ 1e-3` 上的（4.27）相同。

**7. 状态标记各有写明的阈值，且从不互相替代。** 见 `config: criteria`。一次运行是*稳定*的，
指它没有发散（`max_i |y_i| ≤ 1e3`，或出现非有限状态）；*非负*指每个被接受的步节点上
`min_i y_i ≥ -1e-12`；*准确*指 `max_t |y_h - y_ref|_∞ ≤ 1e-4` **且**覆盖整个 `[0, 40]`。
非负性是在**步节点**上量的，也就是方法真正产出的那些点，而不是插值出来的点。

**8. 成本是数出来的，不是估出来的。** 每次运行都记录：右端求值次数、Jacobian 求值次数、
线性求解次数、Newton 迭代次数、接受/拒绝的步数以及墙钟时间。默认的加权成本用
`{rhs: 1, jac: 1, lu: 1}`，以一次 RHS 求值为单位；`config: cost.not_counted` 明确列出**不计入**
的项（解释器开销、免费的密化输出、解析 Jacobian 的组装、I/O、并行）。

**9. 有三样东西是结果的一部分，不是设定。** Jacobian 的差异度必须*连同测它的状态与扰动量*
一起报告，因为它取决于这两者，而且没有普适阈值。Newton 容差必须*和每个结果一起*报告，因为
越过 `h* = √(tol/‖J_f f‖_∞)` 之后它换掉的是方法，而所有便宜的监视器都看不见。被拒绝的步要
*单独*报告、且从不计入任何轨迹统计——它没有发生过。阻尼 Newton 把回溯试算单独列一栏，
这样它才为自己多花的那几次残差求值付了账。

**10. 三个问题始终分开。** 时间步进的稳定性、Newton 的收敛性、时间离散的精度，是三个论断，
各有各的检验。求解成功不能证明它算出的那一步精度如何，守恒缺陷同样不能
（见约定 4 与 Entry 10）。

## P0/P1 结果

### 参考解

Radau，`rtol = 1e-12`，`atol = [1e-16, 1e-22, 1e-16]`，并配合容差重复协议（两个容差也各放宽
100 倍再跑一遍）。重复得到确认：**10.8 位有效数字**，最大绝对偏差 **2.1e-12**。用 BDF 与 LSODA
作为独立的对照，分别一致到 10.7 位和 11.0 位。线性不变量缺陷 ≤ 2.4e-15。

| 量 | 我们的参考值 | 题目给的量级参考值 |
|---|---|---|
| `y1(40)` | 0.71582706872 | 0.7158271 |
| `y2(40)` | 9.1855347646e-06 | 9.1855e-06 |
| `y3(40)` | 0.28416374575 | 0.2841637 |
| `y2` 峰值 | 3.6487e-05，在 `t = 4.4201e-03` | — |

### 刚性比——复现题目给出的核对值

| `t` | 我们的 `S(t)` | 题目核对值 | 比值 |
|---|---|---|---|
| `1e-4` | 3.0097e+03 | 3.0e+03 | 1.003 |
| `1e-2` | 5.4221e+03 | 5.4e+03 | 1.004 |
| `40` | 1.5840e+05 | 1.58e+05 | 1.003 |

`|λ|max(40) = 3392.788`（题目：≈3.39e3）。能复现这些**比值**（而不只是 `|λ|max`）正是上面那条
约化 Jacobian 约定的验证依据：两种约定下 `|λ|max ≈ tr(J)` 是相同的，而行列式不是。

**`S(t)` 并非常数，也不是一开始就很大。** 它从 `t = 1e-8` 处的 `1.67` 升到 `t = 40` 处的
`1.58e5`——大约五个数量级。系统在开头是良态的，随着 `y2`、`y3` 累积才变刚。慢特征值**不是**
`k1 = 0.04`：它在 `t = 40` 处是 `0.0214`，也就是说慢模态比 `1/k1` 还慢。

### 特征值碰撞（F5c）

那两个非零特征值在整个时程上都是实且负的，**除了**一个极窄的窗口
`t ∈ [1.630e-08, 1.705e-08]`，那里判别式略为负（`min disc = -1.07e-6`），它们构成一对共轭，
且 `|Im λ| / |Re λ| ≤ 1.29e-2`。对数值计算的影响：没有（那里的显式 Euler 步长上限约 50，
而 `t = 40` 处是 5.9e-4）。对计算方式的影响：这是一个近二重根，所以特征值是用**精确的迹/行列式
代入求根公式**得到的，而不是用 `np.linalg.eig`——后者在那里噪声明显。固定的 200 点网格正好
跨过这个窗口（落在其中的状态数为 0）；`reference.zoom_reference()` 存在的唯一目的就是解析它，
F5c 面板也如实写着这一点。

### 绝对稳定域（F4）

| 方法 | 阶 | 实轴稳定区间 | A-stable | 由 `|λ|max = 3.39e3` 推出的 `h` |
|---|---|---|---|---|
| 显式 Euler | 1 | `[-2, 0]` | 否 | 5.895e-04 |
| RK4 | 4 | `[-2.7853, 0]` | 否 | 8.209e-04 |
| 隐式 Euler | 1 | `-inf < x ≤ 0` | 是（L-stable） | 无上限 |

RK4 相对显式 Euler 只买到 **1.39** 倍的余量。提高阶数不能治刚性，读匹配精度的成本对比时必须
记着这一点。

## P2 结果

### 冻结 Jacobian 估计：被检验，而不是被断言

`|λ|max(t)` **并不是**在 `t = 0` 处最大。早期快特征值是 `-(k3·y3 + 2·k2·y2)`，而 `y2, y3 → 0`，
所以它很小；最大值出现在轨迹的**末端**，那里 `k3·y3 = 2841.6`、`2·k2·y2 = 551.1`，给出
`|λ|max = 3392.79`。于是 `h < 2/3392.79 = 5.895e-4`（Euler）、
`h < 2.7853/3392.79 = 8.209e-4`（RK4）。

实测扫描（`[1.5e-4, 3e-3]` 上 22 个步长）把这些数夹住了：

| 方法 | 最大稳定 `h` | 首个发散 `h` | 冻结界 | 比值 |
|---|---|---|---|---|
| 显式 Euler | 5.4159e-04 | 6.2464e-04 | 5.8949e-04 | 0.919 |
| RK4 | 8.3088e-04 | 9.5827e-04 | 8.2095e-04 | 1.012 |
| 隐式 Euler | 在 `[1.5e-4, 3e-3]` 内没有 | — | ∞ | — |

两个显式方法的冻结界都落在「最后一个稳定步长」与「第一个发散步长」之间。RK4 比预测**多撑**
1.2%，显式 Euler 比预测**早垮** 8%。两者都在扫描的单个网格步长分辨率之内——对于局部冻结
Jacobian 估计，这已经是能要求的全部了：它是诊断，不是定理。

**三条边界并不重合，而这个差异正是有意思的地方。**

* 显式 Euler：稳定性、非负性与准确性在同一个 `h` 上一起失效（5.4159e-04）。这里不稳定*就是*
  非负性失效——一旦 `|1+hλ| > 1`，模态就会正负交替，把 `y2, y3` 推成负值。最早的发散出现在
  `t = 9.8e-3`。
* RK4：**准确性最先失效**，在 `h = 7.2041e-04`，远早于稳定性（`8.3088e-04`）。存在一个窗口，
  RK4 在那里稳定、非负，但全状态误差已超过 `1e-4`。「没炸」不等于「准」。
* 隐式 Euler：在被扫描的范围内根本没有边界。`h = 3e-3` 时它依然稳定、非负、准确
  （`error < 1e-4`）——稳定性限制是真的消失了，而不只是被推迟。

### 等步长收敛

五个逐次减半的步长 `h ∈ {1e-3, 5e-4, 2.5e-4, 1.25e-4, 6.25e-5}`（即四次减半），每个方法、
每一次运行。`h = 1e-3` 这一档已超出显式方法的稳定界，按「不稳定」如实报告，而不是丢弃。

| 方法 | 标称阶 | **最细一对**的观测阶 | 拟合斜率（`t ≥ 1e-3`） | 拟合斜率（完整网格） |
|---|---|---|---|---|
| 显式 Euler | 1 | **0.998** | 1.079 ± 0.033 | 1.146 |
| RK4 | 4 | **4.023** | 4.268 ± 0.074 | 4.231 |
| 隐式 Euler | 1 | **1.0000** | 0.99996 ± 0.00001 | 0.99996 |

必须写进报告的几点说明：

* RK4 的拟合斜率是 **4.27** 而不是 4.00，因为最粗的那个可用档（`h = 5e-4`）靠近稳定边界，
  那里的误差常数被放大了。**最细一对**给出 4.023，而逐对阶单调下降：4.49 → 4.21 → 4.00。
  只报最小二乘斜率会高估方法；只报最细一对又会掩盖前渐近区。两者都在
  `T8_observed_order.md` 与 F8(c) 面板里。
* 完整网格的斜率与 `t ≥ 1e-3` 的斜率一致，这就是**三次 Hermite 密化输出没有限制观测阶**的证据
  ——题目提醒的那个失败模式本应表现为 RK4 卡在 2 阶。
* 隐式 Euler 的拟合斜率是 `1.0000 ± 0.00001`，`R² = 1.000000`：它的误差就是教科书式的 `C·h`，
  没有任何污染，因为 Newton 求解精确到 `1e-12`，其残差在这个尺度上贡献为零。

### 改变成本对比读法的两件事（P4）

1. **Newton 往往是免费的。** 显式 Euler *预估步*的残差是 `h²·|f_t + J f|`，所以当 `h` 很小时
   它已经低于 Newton 容差，于是不做任何更新。隐式 Euler 实测的每步迭代数：

   | `h` | 每步残差求值次数 | 每步 Newton 更新次数 |
   |---|---|---|
   | 1e-3 | 2.00 | 1.00 |
   | 2.5e-4 | 2.00 | 1.00 |
   | 1.25e-4 | 1.91 | 0.91 |
   | 6.25e-5 | 1.42 | 0.42 |

   在 `h = 6.25e-5` 处，大多数步一上来就在 `1e-12` 内满足隐式方程。那是一个合法的隐式步
   （容差被满足了），**不是** bug——但它意味着隐式 Euler 的每步成本并不是固定的 `(rhs + jac + lu)`
   三元组的常数倍，成本模型必须用实测计数。

2. **守恒对 Newton 容差完全无感。** `(1,1,1)^T` 是 `J` 的左零向量，因此
   `(1,1,1)^T (I - hJ)^{-1} = (1,1,1)^T`，因此一次 Newton 更新就**精确**恢复了总和，无论停机容差
   取多少。这里每一张表里每一次运行的不变量缺陷都是 `~1e-14`——包括那些发散的、出现负值的显式
   运行。这是「守恒单独来看很弱」最锐利的例证，也意味着 P3 的 Newton 容差扫描必须拿**解的误差**
   来评判，而不是看不变量缺陷。

### 关于 P4 成本对比的一条警告（还不是结论）

在匹配精度下读 `T9_cost.md`，对隐式方法而言已经不太舒服：

| 方法 | `h` | 误差（`t ≥ 1e-3`） | 加权成本 | RHS / Jacobian / LU |
|---|---|---|---|---|
| 显式 Euler | 5.0e-4 | 4.481e-06 | 8.00e+04 | 80001 / 0 / 0 |
| 隐式 Euler | 1.0e-3 | 7.355e-06 | 1.60e+05 | 80016 / 40015 / 40015 |

在同样的步数下，显式 Euler 在这里**既更准又更便宜**——因为隐式方法每步都要付一次 Jacobian
求值和一次线性求解，而它的步长优势还没体现出来：在这个区间里显式 Euler 是受**精度**限制、
不是受稳定性限制，而它的精度在 `h = 5e-4` 处已经满足 `1e-4` 了。只有当目标误差松到足以让隐式
方法把 `h` 提到约 `1e-2` 以上，它才会成为更便宜的选择。所以 P4 报告**不能**写那句常见的
「隐式更高效」；它必须说明每个方法在哪个精度水平上取胜，并且要给出这个交叉点对成本权重
（`config: cost.sensitivity_weights`）以及对 Jacobian 是解析还是有限差分求得的敏感性。

## P3 结果

### 1. 四个诊断互相矛盾，而守恒是那个没用的（F9、T13、T14）

这不是风格上的分开陈述。这是关于这个系统的一个定理。`(1,1,1)^T` 是 `J` 的**左零向量**，因此
`(1,1,1)^T (I - hJ)^{-1} = (1,1,1)^T`；对隐式残差 `G(z) = z - y_n - h f(t_{n+1}, z)`：

```
sum G(z) = sum(z) - sum(y_n)        （因为 (1,1,1)^T f ≡ 0）
=>  一次 Newton 更新后，sum(z + dz) = sum(z) - sum(G | z) = sum(y_n)
```

**每一次 Newton 迭代都精确保持总和**，无论停机容差取多少——包括显式 Euler 预估步，
也包括零更新的情形。在 `h` 扫描（T13）上实测：

| `h` | 方法 | 守恒缺陷 | `min_i y_i` | 误差 | 判定 |
|---|---|---|---|---|---|
| 1.5e-4 | 三种 | 9.5e-15 … 2.2e-14 | 0.0 | 4.6e-10 … 1.2e-6 | 四轨全过 |
| 8.31e-4 | RK4 | 6.2e-15 | 0.0 | **1.24e-4** | 守恒、稳定、非负都过；**准确性失效** |
| 1.27e-3 | 显式 Euler | 2.4e-15 | **−42.9** | **2.3e-2** | 只有守恒还过 |

（这三行逐格抄自 `T13_four_track.md`。本表早先的版本写的是 `h = 1.5e-3`、`min_i y_i = −13.7`、
`4.8e-2`，以及 RK4 的守恒缺陷 `2e-14`；这些值在任何扫描表里都不存在——扫描网格上没有 `1.5e-3`
这个点，而 `8.3088e-4` 处 RK4 的缺陷是 `6.2e-15`。同一行错误数字也曾出现在一版幻灯片草稿里，
在那里被发现；见透明度日志的 Entry 11，以及记录 README 这次出现的 Entry 13。）

中间那一行就是全部要点：一次运行可以是稳定的、非负的，却依然是错的，而且任何不变量缺陷都
不会说出来。四轨由四组不同的列算出，允许它们互相矛盾
（`T14_four_track_boundaries.md` 记录每条轨道在哪里不再被满足，以及*哪一条先失效*）。

### 2. 隐式方法的终点值 `y2(40)`（T10）

只引用被我们自己收紧的参考解确认过的位数（参考解整体可信到 10.76 位，其中 `y2` 到 **10.16** 位，
最大绝对偏差 2.09e-12）。`y2(40)` 在两个步长 × 两个 Newton 容差下报告：

| `h` | Newton 容差 | `y2(40)` | 相对参考解的一致位数 |
|---|---|---|---|
| 1.0e-3 | 1e-8 | 9.1840386117e-06 | 3.79 |
| 1.0e-3 | 1e-12 | 9.1856705286e-06 | 4.83 |
| 2.5e-4 | 1e-12 | 9.1855687065e-06 | 5.43 |
| 6.25e-5 | 1e-12 | **9.1855387584e-06** | **6.36** |

收敛是一阶的（它必然如此），所以位数来自步长，而不是来自 Newton 容差——一旦容差足够紧
（见下），它就不再起作用。我们的参考解把题目给的量级参考值 `y2 = 9.1855e-06` 确认到
**5.42 位**，所以 `9.1855` 可以引用，下一位不可以。（另附：`y1 = 0.7158271` 被确认到 7.36 位，
`y3 = 0.2841637` 到 6.79 位。）

### 3. Newton 不必解到精确，而安全容差由 `h²` 决定，不是凭直觉（F10、T11）

显式 Euler 预估步的残差是

```
G(y_pred) = h [ f(t_n, y_n) - f(t_{n+1}, y_pred) ] = -h² (f_t + J f) + O(h³)
```

所以一旦停机容差超过大约 `h² |f_t + J f|`，**第一次**残差检验就会通过，这一步便在
**零次 Newton 更新**下被接受——隐式 Euler 静默地退化成右端项取滞后的显式 Euler。
在 `h = 10⁻³` 处这个尺度就是 `h² = 10⁻⁶`，而扫描恰好把断点放在那里：

| Newton 容差 | 误差（完整网格） | 相对平台的膨胀倍数 | 每步 Newton 更新次数 | 跳过一次 Newton 的步占比 |
|---|---|---|---|---|
| 1e-2 | 1.44e+02 | 19602817 | 1.18 | 60% |
| 1e-4 | 3.59e+02 | 48855880 | 0.77 | 60% |
| **1e-6** | 1.96e-05 | **2.67** | 0.30 | 70% |
| **1e-8** | 6.44e-06 | **0.88** | 0.31 | 69% |
| 1e-10 | 7.35e-06 | 1.00 | 0.82 | 18% |
| 1e-12 | 7.35e-06 | 1.00 | 1.00 | 0% |
| 1e-14 | 7.35e-06 | 1.00 | 1.00 | 0% |

* **平台值** `= 7.355e-06`，出现在最紧的容差处：那是纯粹的离散化误差。
* **推荐的停机容差是 `1e-8`**，是能让代数误差保持可忽略的最大值（膨胀 0.88——误差在那里其实
  *小于*平台值，因为代数误差与离散化误差部分抵消；膨胀倍数正是相对最紧容差来定义的，原因就在此）。
* **首个破坏点是 `1e-6`**，膨胀 2.67。
* **不变量缺陷作为监控量是没用的**：在 `tol = 1e-2` 处误差是 144、`min_i y_i = −143.8`，而守恒
  缺陷是 1.9e-12。F10(a) 面板把缺陷与理论包络 `3·tol` 画在一起：这个界处处满足，携带的信息为零。
* Newton 很**便宜**：紧容差下每步一次更新，松容差下连那一次都省了。成本模型必须用实测计数，
  不能用一个固定倍数。

### 4. 自适应步长：控制器有效，而一个看起来显然的误差范数无效（F11、T12）

RK4 步长加倍，`err = |y_half − y_full| / (2⁴ − 1)`、`safety = 0.9`、`facmax = 5`、`facmin = 0.2`，
接受判据为逐分量加权 `max_i |e_i| / (atol_i + |y_i|) ≤ tol`。

**（a）步长确实在动**（F11a）：它穿过诱导层时急剧塌缩（`t = 1e-6` 处 `h ≈ 5e-7`），随后进入平台。
平台才是要点：

| tol | 控制器 `h` 的中位数 | 子步 `h/2` ÷ 冻结界 的中位数 | `err/tol` 中位数 | 接受 / 拒绝 |
|---|---|---|---|---|
| 1e-4 | 1.754e-03 | **1.07** | 0.18 | 20745 / 8127 |
| 1e-6 | 1.763e-03 | **1.07** | 0.19 | 20772 / 9241 |
| 1e-8 | 1.742e-03 | **1.06** | 0.31 | 22053 / 8317 |
| 1e-10 | 1.363e-03 | 0.83 | 0.59 | 31259 / 1 |

对每一个松到 `1e-8` 的容差，**实际推进用的子步 `h/2` 都停在冻结 Jacobian 界 8.209e-4 上方
6–7%**——控制器是受*稳定性*限制、而不是受精度限制，这正是 `err/tol ≈ 0.2 ≪ 1` 所说明的。
拒绝集中在那个平台上（F11a 里的灰色叉号），而一旦精度在 `tol = 1e-10` 处接管，拒绝就消失了
（只剩 1 次）。这与 F7 形成闭环：冻结界是一个局部的、线性的估计，然而一个实现正确的控制器的
*实际*步长，从下方逼近它到 7% 以内。

**（b）被控制的是局部误差，不是全局误差**（F11b/c）。`err/tol` 在每个被接受的步上都低于 1，
中位数大致恒定（0.18 → 0.59）。而 `t = 40` 处的*全局*误差大约要大出一个步数的量级：

| tol | 1e-4 | 1e-6 | 1e-8 | 1e-10 |
|---|---|---|---|---|
| 全局误差 | 3.23e-07 | 9.93e-09 | 1.99e-12 | 3.29e-14 |

大致与 `tol` 成正比，步数 `N ≈ 2e4`，所以 `全局 ≈ 0.03 · N · tol`。`tol = 1e-10` 那次已经落在
参考解的误差地板上——再收紧什么也买不到。F11(c) 如实说明这一点，而不是宣称「误差 ≈ 容差」。

**（c）普通 `L∞` 范数看不见的那个失效**（F11c，控制组的 F11b）。`y1 = O(1)` 而 `y2 = O(1e-5)`。
用普通绝对范数时，`y2` 里 `1e-2` 的相对误差对 `err` 只贡献 `1e-7`，所以在 `tol = 1e-6` 处控制器
**接受了超出 RK4 稳定界的步**：

| 范数 | tol | 到达 | `min_i y_i` | 全局误差 | 守恒缺陷 |
|---|---|---|---|---|---|
| 绝对 `L∞` | 1e-4 | **只到 t = 1.9** | **−903** | 2.17e-03 | 1.1e-13 |
| 绝对 `L∞` | 1e-6 | 40 | **−4.77e-05** | **7.83e-03** | 7.8e-15 |
| 加权 | 1e-6 | 40 | 0.0 | **9.93e-09** | 5.8e-15 |

同一个控制器、同一个容差，精度差 `10⁶` 倍——而两种情况下不变量缺陷都在 `1e-13` 或以下，
也就是说，什么都没报出来。两个变体都留在仓库里，都跑、都列表；失效是被报告的，不是被藏起来的。
（三个缺陷值是在后来的一次复核中按 `T12_adaptive.md` 更正的，原写作 `1.9e-15`、`2.2e-14`、
`2.1e-15`；这张表其余每个单元格本来就是对得上的。见透明度日志 Entry 14。）

## Tutorial 2 补做——第一版没有做的三项检查

Tutorial 2 把三个问题分得很清楚，而本工作第一版把它们混在了一起：

1. **时间步进稳定吗？** 这是 `R(z)` 在实际谱上的性质，也就是 A-稳定 / L-稳定的讨论。
   隐式 Euler 两者都是，显式 Euler 两者都不是。
2. **Newton 收敛吗？** 这是*求解*的性质，不是轨迹的性质，它有自己的一套验收判据。
3. **时间离散精度够吗？** 这是 `O(h^p)`，也是误差估计量本该盯住的东西。

第一版有（1）和（3），把（2）当成（3）里面的一个旋钮。这一轮补了三项具体检查，各产出一张表、
其中两项还产出一张图。三项中有两项改掉的是一个**论断**，而不只是一个数字。

### 5. 阻尼 Newton：冷启动必需，驱动路径从不需要（T16）

T16 让 Newton 从**旧状态**出发。这是一个冷启动，而且是差的冷启动：`h = 40` 时第一个方向就是
大幅过冲，无阻尼 Newton 要 21 次更新——超出 Tutorial 给的「最多 10 次更新」额度。

| `h` | 满 Newton 方向数 | 阻尼方向数 | 回溯次数 | 试算次数 | 右端调用（满 / 阻尼） | 同一个根 |
|---|---|---|---|---|---|---|
| 1.0e-4 | 3 | 3 | 0 | 3 | 4 / 7 | 是 |
| 1.0e-2 | 8 | 5 | 4 | 9 | 9 / 15 | 是 |
| 1.0e-1 | 12 | 5 | 7 | 12 | 13 / 18 | 是 |
| 1.0e+0 | 15 | 6 | 11 | 17 | 16 / 24 | 是 |
| 4.0e+1 | 21 | 5 | 15 | 20 | 22 / 26 | 是 |

从 `α = 1` 开始折半回溯、只在 `‖G‖` 下降时接受，方向数就被压在 `[3, 6]`，横跨四个数量级的
`h`；而满 Newton 从 3 涨到 21。Tutorial 的判据在这个扫描网格上阻尼版处处满足、无阻尼版从
`h = 1e-1` 起就不满足了。两个变体每一步返回**同一个状态**，误差 `1e-11`——所以阻尼改的是成本，
不是答案，这正是要点。成本列分成「方向数」和「试算次数」两栏，因为一次回溯要多算一次残差；
只统计收敛更新数的表会让阻尼看起来是免费的。

**但驱动路径从不需要它，而本节早先的草稿说了反话。** 那一版写「`h` 一大这个预测子初值就很差」
——`ImplicitEuler._step` 其实是用**免费的显式 Euler 预测子** `y + h f(t_n, y)` 热启动的，那是个
**好**初值，而这句话从来没有在驱动路径上量过。实量结果（`[0, 40]` 全程）：

| `h` | 步数 | 变体 | 总更新次数 | 每步最多 | 回溯次数 | 右端调用 | `y2(40)` |
|---|---|---|---|---|---|---|---|
| 1e-2 | 4 000 | 满步 | 4 014 | 7 | 0 | 8 015 | 9.186892e-06 |
| 1e-2 | 4 000 | 阻尼 | 4 014 | 7 | 0 | 12 029 | 9.186892e-06 |
| 1e-3 | 40 000 | 满步 | 40 015 | 4 | 0 | 80 016 | 9.185671e-06 |
| 1e-3 | 40 000 | 阻尼 | 40 015 | 4 | 0 | 120 031 | 9.185671e-06 |

44 000 步里**一次回溯都没有**，更新总数完全相同，终值完全相同，而阻尼版付了 `1.50` 倍的右端调用
去养一个从不触发的保险。**让驱动路径上 Newton 单调收敛的是那个免费预测子，不是阻尼。** 阻尼是
冷启动的正确保险——而 Tutorial 那条判据针对的正是冷启动。这次更正记在透明度日志 Entry 18。

最后一栏才是要带走的结论：**求解成功，完全不说明它算出的这一步精度如何。**

### 6. 解析 Jacobian 的独立校验（T17、F15）

`J` 在这个项目里到处都在用，而在这轮补做之前从来没被校验过。校验用逐列前向差分——

```
(J)[:, j]  ≈  ( f(t, y + eps_j e_j) - f(t, y) ) / eps_j ,
eta = ||J_A - J_D||_inf / max(1, ||J_A||_inf)
```

——残差 Jacobian `J_F = I - h J_f` 也一并差分，因为隐式 Euler 真正求解时用的是它。

| 状态 | 用 `√ε_mach · max(1,|y_j|)` 的 `η` | 用调优 `ε` 的 `η` | `η(J_F)`（用它自己调优的 `ε`） |
|---|---|---|---|
| 初始 | 4.470e-01 | 3.048e-05 | 3.006e-07 |
| 瞬态 | 2.503e-04 | 1.935e-08 | 1.077e-07 |
| 末端 | 1.318e-04 | 9.250e-09 | 8.712e-08 |

有三件事是靠测量而不是靠声明立住的：

* **不存在通用阈值。** 在 `y(0)` 处，*正确*的 Jacobian 在经验扰动下就得 `4.47e-01`；用 `1e-8`
  当门槛会把它判为错。扰动扫描的最小值在 `ε = 1e-12`，比经验值低四个数量级，而曲线**两侧**都
  在上升——左边是相消，右边是截断。所以 `η` 永远和状态、扰动量一起报告。
* **只看一个状态不叫校验。** 把整个 `10⁴ y₂y₃` 反应从 `J_f` 里删掉再跑，在 `y(0)` 处分离度
  **恰好 1.000**：那里 `y₂ = y₃ = 0`，这个 bug 触及的四个元素在正确矩阵里也是零，两个矩阵完全相同。
  同一个 bug 在瞬态状态分离 `1.2e4×`，在末端状态分离 `9.1e7×`（调优 `ε`）。
* **校验很便宜。** 整个协议花 132 次右端求值。

### 7. Newton 容差松了不是「丢精度」，而是换了一个方法（T18、F14）

这一条改掉的正是论断本身。Newton 在更新之前先测残差，而预测子的残差是

```
G(y_pred) = -h² J_f f + O(h³)
```

于是只要 `h ≤ h* = √(tol / ‖J_f f‖_∞)`，预测子就被**零次更新**接受——这一步字面上就是显式
Euler 步。在 `t = 1.0227` 处 `‖J_f f‖_∞ = 8.2324e-03`，所以 `tol = 1e-6` 给出 `h* = 1.1e-02`，
而这道题显式 Euler 的实测稳定界是 `h < 5.895e-4`。也就是说，`tol = 1e-6` 的控制器会接受**超出
它其实在跑的那个方法的稳定界 19 倍**的步长。

本该盯住步长的那个估计量看不见这件事：

| `h` | `E`（`tol = 1e-14`，更新数 `1,1,1`） | `E`（`tol = 1e-6`，更新数 `0,0,0`） | 比值 |
|---|---|---|---|
| 1e-03 | 2.908e-09 | 2.910e-09 | 1.0007 |
| 5e-03 | 7.247e-08 | 7.274e-08 | 1.0037 |
| 1e-02 | 2.887e-07 | 2.909e-07 | 1.0076 |

两个 Euler 方法都是一阶，`E ~ h²` 在两种情况下都成立——七个容差拟合出的 `h` 幂次全落在
`[1.89, 2.10]` 之内，那只是拟合本身的宽度。估计量回答的是「我跑的这个方法局部误差多大」，
它回答得很对；它回答不了「我刚跑的是哪个方法」。一阶估计量区分不了两个一阶方法。

**而它同时又背着求解器自己的误差。** `E = ‖y_f − y_c‖` 是两侧之差，所以一旦粗侧和两个半侧的
代数精度不同，这个不匹配就直接落进估计量里。把 T18 的第二张表格竖着读：凡是更新三元组是
`(1,0,0)` 的格子，数值**恰好是**相邻一致行的 `3.00×`；凡是三元组一致的格子，数值到最后一位
打印数字都相同。这就是 Tutorial 那句「Newton 误差必须小到不足以主导这个差」，只不过是以测量
的形式写出来的。

两个便宜的监视器都漏掉了这个切换。守恒量按构造就对此不敏感（`(1,1,1)ᵀ` 是 `J_f` 的左零向量，
一次更新就能在任意容差下精确恢复不变量——而容差松的时候根本没有更新，预测子本身就守恒）。
局部误差估计量如上所述是瞎的。三者之中只有「对参考解的实测轨迹误差」看得见它，这就是为什么
在这个项目里 Newton 容差是和每个结果并列报告的，而不是被假定的。

切换阈值随 `tol` 变化，而且动得很慢，因为 `h* ∝ √tol`：

| `tol` | `h*` | `h*` ÷ 显式 Euler 稳定界 |
|---|---|---|
| 1e-14 | 1.10e-06 | 0.002 |
| 1e-12 | 1.10e-05 | 0.02 |
| 1e-10 | 1.10e-04 | 0.19 |
| **1e-08** | 1.10e-03 | **1.87** |
| 1e-07 | 3.49e-03 | 5.91 |
| **1e-06** | 1.10e-02 | **18.70** |
| 1e-04 | 1.10e-01 | 186.97 |

所以收紧容差不会消除这个替换，只是把 `h*` 往下推——而买一个数量级的安全要付出**两个**数量级的
容差。没有任何一个容差能让隐式 Euler 在 `h ≫ 1e-3` 处变安全；让这一步仍然是隐式步的，是*步长*
留在 `h*` 以下。第 3 节那条推荐因此准确的表述是：`tol = 1e-8` 是能让代数误差保持可忽略的最大
容差，而在 P3 扫描用的 `h = 1e-3` 处，它已经在跑略高于显式稳定界的显式 Euler 了；`tol = 1e-6`
则是把同一件事放大十九倍。把容差和每个结果一起报告、而不是假定它足够紧，因此不是形式主义。

## 幻灯片（beamer）

`slides/robertson_slides.tex` 生成一份 27 页、16:9 的 beamer 幻灯片（标题页 + 26 帧，
其中十四帧是备份）。metropolis 主题，正文中文、方法名保留英文，用 `ctex` + Fandol 字体，
因此不依赖任何系统 CJK 字体。

这份幻灯片是讲给第一次接触 Robertson 问题的听众的，所以主线**不是**按计算阶段排列的。它走的是：

> 要解决什么 → 答案长什么样 → 难在哪 → 怎么做 → 四条结论 → 总结

十二帧主线承载这条脉络（标题页 + 12 帧）。所有只有已经熟悉这套术语的读者才会想看的技术内容——
谱与结构零特征值、`S(t)` 与题目核对值的对比、稳定域、观测阶、四轨边界表、`y2(40)` 的位数、
完整的 Newton 扫描、容差换方法、Jacobian 校验、阻尼 Newton 的成本表、自适应范数失效、
文件清单、Tutorial 2 小结——都放在十四帧备份里，只在需要时翻出来。
首版讲稿把这些内容混排在一起，这正是它读起来像目录而不像论证的原因；见透明度日志 Entry 12。

```sh
cd slides
tectonic -X compile robertson_slides.tex --outdir build   # 生成 build/robertson_slides.pdf
```

关于这份幻灯片如何保持诚实：

* **帧里的数字没有一个是凭记忆手敲的。** 每一个表格单元格、每一个引用的数字，都是在
  `run_all.py` 成功运行之后，从 `results/tables/*.md` 或 `results/summary.json` 抄出来的，
  然后再逐格与那些文件核对。有一行草稿（显式 Euler 的非负性行）**没有**通过这道检查——
  它的值在任何表里都不存在，于是被替换成取自 T5/T13 的行，并记入日志。
  Entry 15–18 是同一套纪律用在**代码**那一侧：被核对的是一个论断，而不是一个单元格。
* 图以 **PDF** 形式从 `../results/figures/` 引入，所以幻灯片保持矢量，F9–F15 里的注解放大后
  仍然清楚。
* 编译只剩一条警告：metropolis 自带标题页模板里的 13.8 pt `Overfull \vbox`。渲染页面上不切
  任何内容，只是那个盒子比版心高。**我们自己的帧没有任何一帧需要 `[shrink]` 键。** 重写去掉了
  原先那五处：过去需要 `[shrink=8]` 的帧现在靠结构调整就装得下（两张 4 列数值表被**转置**、
  一张全宽三面板图移进栏内、成本表归一到公共单位 `10^5`），两帧 `[shrink=2]` 已不再是主线帧，
  而透明度日志那一帧重新排版成「上方双栏 + 下方通栏清单」，让 18 条全部容得下。
  Tutorial 2 补的三帧同样守这条规矩：两帧图把图放进**栏内**而不是通栏压在上面，
  「本次新增」里那个四项嵌套列表被拆成独立一帧而不是硬塞。三帧都经过两轮编译、全程没用
  `[shrink]`——从 112 pt、93 pt、95 pt 溢出修到零。
